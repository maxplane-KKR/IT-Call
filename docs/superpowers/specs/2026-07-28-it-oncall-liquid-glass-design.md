# IT On-call Compensation Desk Liquid Glass Design

**Date:** 2026-07-28  
**Status:** Approved for local reconstruction  
**Scope:** Local preview only; no production deployment in this phase

## Goal

Reconstruct the existing IT On-call Compensation Dashboard as a responsive,
accessible Liquid Glass dashboard that preserves the current information model
and interaction intent while making status, compensation, analysis, and event
records easier to scan on desktop and mobile.

## Context and constraints

- The local workspace does not contain the original site source, so this phase
  uses a local reconstruction based on the current dashboard surface.
- The reconstruction must use local sample data and local-only interaction
  state; it must not claim to be connected to production data.
- Existing product concepts remain: on-call status, rate cards, month,
  operator, event type, department, KPI cards, analysis panels, event records,
  access notice, and CSV export affordance.
- Production publishing is explicitly out of scope until the local preview is
  reviewed and approved.

## Recommended visual direction

Use a dark operational-glass system rather than a light frosted-glass system.
The base canvas is deep navy/ink, with translucent surfaces, a restrained blue
primary accent, green/amber/red status colors, and clear text contrast. Blur is
used to separate layers and reinforce hierarchy, not as a decorative effect on
every element.

The design system generated by `ui-ux-pro-max` is persisted at
`design-system/it-on-call-compensation-desk/MASTER.md` and is the source of
truth for palette, Fira Sans/Fira Code typography, dense dashboard spacing,
motion restraint, and responsive breakpoints.

### Core tokens

- Canvas: `#06101F` with subtle radial blue/teal atmosphere
- Glass surface: white at 8-12% opacity with 1px white border at 12-18%
- Primary text: `#F8FAFC`; secondary text: `#B6C4D5`
- Primary accent: `#69A8FF`; positive: `#4ADE80`; warning: `#FBBF24`;
  critical: `#FB7185`
- Radius: 18px for panels, 12px for controls, 999px for pills
- Shadow: low, wide blue-black shadow; no hard card drop shadows
- Type: Fira Sans for interface copy, Fira Code for metrics and timestamps
- Motion: 150-300ms transitions; no looping decorative animation;
  `prefers-reduced-motion: reduce` disables entrance and atmospheric motion

## Page structure

1. **Top shell**
   - Product mark and Thai descriptor
   - Current dashboard label and compact live-status pill
   - One primary “อัปเดตข้อมูล” action with disabled/loading feedback
   - On mobile, the shell wraps into two rows without clipping

2. **Hero status panel**
   - “IT On-call” title and concise Thai purpose statement
   - Next refresh countdown and last-updated text
   - Four rate tiles: ค่าเวร, Tele, ทั่วไป, เพดาน
   - Loading state uses skeleton blocks while sample data initializes

3. **Dashboard filters**
   - Month, operator, event type, and department
   - Native select controls with visible labels and keyboard support
   - A “ล้างตัวกรอง” action appears only when a filter is active
   - Filter changes update the sample view without navigation or page reload

4. **Key metrics**
   - Five KPIs: paid compensation, on-call shifts, Tele events, general events,
     and capped amount
   - The first KPI is visually primary; other cards are subordinate but remain
     readable without relying on color alone
   - Values use tabular/code numerals to avoid layout shifting

5. **Analysis grid**
   - Four panels: compensation by operator, event-type mix, busiest reporting
     window, and operator case share
   - Charts are lightweight CSS/SVG data visuals with text summaries and labels
     so the local preview has no chart-library dependency or blank-canvas state
   - Small screens stack panels in priority order: compensation, event mix,
     busiest window, operator share

6. **Event log**
   - Section header with “บันทึกปฏิบัติการ” eyebrow and record count
   - Desktop table columns: date/time, operator, department, event type,
     severity/status, duration, and compensation
   - Mobile uses stacked record cards with the same fields and a clear status
     label
   - Access notice remains visible above the records
   - CSV action is local-only and exports the visible sample records when used

## Responsive behavior

- 375px: single-column content, 2-column KPI grid, compact filter controls,
  stacked analysis and event cards; no horizontal page scroll
- 768px: two-column KPI and analysis layouts where content remains legible;
  filters become a two-column grid
- 1024px: desktop shell begins; hero and status summary can share a row
- 1440px: content max-width is capped for readable line length and balanced
  negative space; analysis grid uses four columns where appropriate
- All interactive controls retain at least 44px visual/hit height and an 8px
  minimum gap. The layout supports landscape without hiding the event list.

## Data and interaction model

The local page owns a small typed sample dataset with operators, departments,
event types, dates, durations, severity, and compensation values. Derived KPI
and analysis values are calculated from the currently filtered records, so the
preview demonstrates the intended behavior rather than presenting static
decorative numbers.

The update button simulates a short refresh cycle: it enters a loading state,
shows feedback, updates the “last updated” timestamp, and returns to an enabled
state. The countdown is non-blocking and pauses cleanly when the page is not
visible. Filter controls are deterministic and preserve their selected values.

## Loading, empty, and error states

- Loading: show skeleton content for status, KPI, and analysis areas; keep the
  page structure stable to avoid layout shift.
- Empty filtered result: show a concise explanation and a “ล้างตัวกรอง” action;
  do not show an empty chart frame.
- Export failure: show an inline error with a retry action and `aria-live` text.
- Reduced motion: preserve the same information and feedback with opacity
  changes only or no animation.

## Accessibility and quality requirements

- Use semantic headings, landmarks, table semantics on desktop, and descriptive
  labels for icon-only actions.
- Provide visible keyboard focus rings and a logical focus order.
- Maintain at least 4.5:1 contrast for normal text and do not use color as the
  only status signal; pair status colors with text/icon labels.
- Use consistent outline iconography rather than emoji glyphs.
- Respect `prefers-reduced-motion` and avoid hover-only actions.
- Keep body text at 16px or larger on mobile and preserve readable line length
  on desktop.

## Validation plan

1. Run the project build and confirm a clean exit.
2. Open the local dev URL and verify the first viewport on desktop.
3. Check responsive layouts at 1440px, 1024px, 768px, and 375px.
4. Verify filter changes, reset, update loading feedback, empty state, and CSV
   sample export.
5. Verify keyboard tab order and visible focus on controls.
6. Verify reduced-motion rendering and that no horizontal scroll is introduced.
7. Keep the local preview available for user review; do not save or deploy a
   production Sites version in this phase.

## Acceptance criteria

- The local preview clearly reads as an IT on-call compensation dashboard,
  retains the current content model, and uses Liquid Glass consistently.
- Desktop and mobile layouts are both complete and usable without horizontal
  scrolling or clipped controls.
- Sample-data interactions update KPIs and analysis panels coherently.
- Loading, empty, access-notice, and update feedback states are present.
- The build passes, the local URL is accessible, and responsive checks have
  fresh browser evidence before claiming completion.
