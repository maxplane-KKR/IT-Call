# Mobile Reports Design

## เป้าหมาย

ปรับส่วนสรุปยอดภาระงานรายบุคคลและรายการแจ้งปัญหาให้ใช้งานบนมือถือได้เต็มความกว้าง โดยไม่มีการเลื่อนแนวนอน ตั้งแต่หน้าจอ 320 พิกเซลขึ้นไป ขณะที่หน้าเดสก์ท็อปยังคงรูปแบบเดิม

## สาเหตุปัจจุบัน

ทั้งสองส่วนใช้ตารางเดสก์ท็อปหลายคอลัมน์ภายในกล่อง `overflow-x-auto` บนมือถือ จึงเกิดแถบเลื่อนแนวนอน ข้อมูลด้านขวาถูกตัด และต้องเลื่อนเพื่ออ่านข้อมูลหนึ่งรายการให้ครบ

## โครงสร้างที่เลือก

### สรุป HR บนมือถือ

- ซ่อนตารางเดสก์ท็อปเมื่อความกว้างไม่เกิน 600 พิกเซล
- แสดงรายการอันดับสำหรับมือถือโดยเฉพาะ
- แต่ละรายการแสดงลำดับ อวตาร ชื่อผู้ปฏิบัติงาน จำนวน Ticket เปอร์เซ็นต์ และแถบสัดส่วน
- แสดงยอดรวมท้ายรายการ
- ข้อความยาวตัดด้วย ellipsis และเก็บค่าเต็มใน `title` กับ `aria-label`

### Log บนมือถือ

- ซ่อนตารางเดสก์ท็อปเมื่อความกว้างไม่เกิน 600 พิกเซล
- แสดงหนึ่งเหตุการณ์ต่อหนึ่งการ์ด
- ส่วนหัวการ์ดแสดงวันที่และเวลา
- รายละเอียดปัญหาแสดงแบบตัดบรรทัดได้เต็มความกว้าง
- ประเภท แผนก และผู้ปฏิบัติงานแสดงเป็นข้อมูลรองที่อ่านง่าย
- ใช้ pagination ชุดเดิมร่วมกัน เพื่อไม่เปลี่ยนพฤติกรรมการค้นหาและตัวกรอง

### ตัวกรองและปุ่ม

- บนมือถือ select และช่องค้นหาใช้ความกว้างเต็ม
- ปุ่มดาวน์โหลดมีข้อความกำกับและจัดวางโดยไม่ดันหน้าจอให้ล้น
- ปุ่มในส่วน HR เรียงเต็มความกว้างและกดได้สะดวก

## การแยกโค้ด

- ใช้ markup มือถือแยกจาก markup เดสก์ท็อป
- เพิ่มฟังก์ชันเรนเดอร์มือถือสำหรับ HR และ Log โดยรับข้อมูลชุดเดียวกับฟังก์ชันเดสก์ท็อป
- แยกตัวช่วยสร้างข้อมูลที่ใช้ร่วมกัน เพื่อลดโอกาสที่ค่าบนมือถือกับเดสก์ท็อปไม่ตรงกัน
- CSS มือถือทั้งหมดอยู่ภายใน media query ไม่เกิน 600 พิกเซล

## การเข้าถึงและสถานะ

- รายการมือถือใช้ semantic list/article และมีชื่อกำกับที่ screen reader อ่านได้
- สถานะไม่มีข้อมูลแสดงทั้งเดสก์ท็อปและมือถือ
- เนื้อหาที่ตัดด้วย ellipsis มีค่าฉบับเต็มสำหรับผู้ใช้เทคโนโลยีช่วยเหลือ

## การตรวจสอบ

- เพิ่มการทดสอบว่า markup และฟังก์ชันเรนเดอร์มือถือมีอยู่และได้รับข้อมูลครบ
- ตรวจการค้นหา ตัวกรอง และ pagination ว่าอัปเดตทั้งสองเลย์เอาต์
- ตรวจหน้าเว็บที่ 320×800, 360×800 และ 390×844
- เกณฑ์ผ่าน: ไม่มี horizontal overflow, ข้อมูลทุกช่องอยู่ในจอ, เดสก์ท็อปไม่เปลี่ยน และชุดทดสอบเดิมผ่านทั้งหมด
